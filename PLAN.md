## План рефакторинга

### 1. Цели
- Разделить доменную логику, интеграции и инфраструктуру по слоям.
- Упростить поддержку за счёт единых клиентов Bitrix/Alma и повторно используемых валидаторов.
- Удалить код записи ошибок в базу данных (оставить только файловые логи) без изменения `objects_app`.

### 2. Целевая структура (по образцу Laravel)
- `public/` – единственная точка входа (`index.php`) для вебхуков/CLI, подключение автозагрузки.
- `app/Http/Controllers` – тонкие контроллеры для сущностей (апартаменты, юниты, арендаторы, контракты).
- `app/Console/Commands` – CLI-команды для ручных запусков/cron.
- `app/Services` – бизнес-логика синхронизации (например, `ApartmentSyncService`).
- `app/Clients` – HTTP-клиенты для Bitrix и Alma с едиными настройками CURL.
- `app/Mappings` – конфигурация полей/enum (замена `ProjectMapping.php`).
- `app/Support/Logging` – Logger/ActionLogger без DB-трекинга.
- `bootstrap/app.php` – инициализация контейнера зависимостей и конфигурации.

### 3. Основные задачи
1. **Инфраструктура**
   - Настроить Composer, пср-4 для `app/`.
   - Перенести `Config` в сервис `ConfigurationRepository`.
   - Создать простой контейнер зависимостей (или статический `App::make()`).
2. **Клиенты**
   - Объединить все CURL-вызовы Alma в `AlmaRealtyClient`, `AlmaUsersClient`.
   - Обернуть Bitrix в `BitrixApiClient` с повторными попытками и логированием.
3. **Сервисы**
   - Реализовать сервисы синхронизации по сущностям.
   - Перенести бизнес-правила из `appart.php`, `tenant.php`, `landlord.php`, `tenatContract.php`, `landlordContract.php`, `unit.php`.
4. **Контроллеры/Команды**
   - В `public/index.php` определить маршрутизацию → контроллер → сервис → ответ.
   - Создать консольные команды для единичного запуска (аналог текущих PHP-скриптов).
5. **Логирование и ошибки**
   - Оставить `Logger`/`ActionLogger`, но убрать обращения к БД в `EnhancedLogger`/`ErrorTracker`.
   - Для аналитики подготовить формат JSON-логов с ключевыми полями.
6. **Конфигурация и маппинги**
   - Разложить конфигурацию проектов по файлам (`config/projects.php`, `config/mappings.php`).
   - Ввести вспомогательные классы для преобразования полей (например, `ContractDataTransformer`).
7. **Параллельное существование**
   - На первом этапе запускать новый код через отдельные endpoints, сравнивать результаты с legacy.
   - После стабилизации удалить старые скрипты.

### 4. Шаги миграции
1. Подготовить каркас (`public`, `bootstrap`, автозагрузка, базовый контейнер, логгер без БД).
2. Перенести `ProjectMapping` в набор конфигурационных файлов и адаптеров.
3. Создать клиентов Alma/Bitrix и покрыть их юнит-тестами (минимум моки ответов).
4. Вынести синхронизацию квартир в сервис + контроллер, подключить к webhook.
5. Последовательно перенести остальные сущности (юниты, арендаторы, лендлорды, контракты).
6. Обновить cron/CLI на использование новых команд.
7. Очистить неиспользуемые файлы, оставить обратную совместимость только при необходимости.
